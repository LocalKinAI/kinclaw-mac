# Studio 路线图 — 从四个工作台到超级工作室

**日期**: 2026-09-26
**状态**: 提议
**基于**: `main` @ `552f4ca`(快速出图 + agent 笔记本)
**关联**: [`CHANGELOG.md`](../CHANGELOG.md) `[Unreleased]` 里 "The Studio, worked by its agents"、"An agent on each Studio tab"、"Montage" 三节

---

## 一句话

一句话进、一部片出,全在自己的机器上 —— 而且一天能出很多部、每部都不比上一部差,agent 自己发现问题、自己交接。

---

## 现在有什么

| 工作台 | 做什么 | agent 的工具 |
|---|---|---|
| **Film** | 一句话 → 选角、分镜、首帧(Qwen-Image)、H3/LTX 拍摄、旁白、配乐、剪辑、片名/调色/放大 | film_* + comfy_* |
| **Motion** | 她的动作、3D 场景、运镜 | motion_find / make / status / stop / continue |
| **Comfy** | ComfyUI 的现成工作流,做成表单 | comfy_* |
| **Montage** | OpenMontage 在盒子上,Backlot 看板拉回本机 | om_bridge(list/read/look/write/run/job) |

- 四个 agent **各自独立**(对话、文件夹、大脑都分开),每个只拿到自己台子的工具。这是定下的方向,不改。
- 大脑可以是 Claude 订阅、Codex、本机或盒子的 Ollama、kinfer —— 不按调用计费。
- 9/25 起 agent 能真正驱动:给的就照用、能停在 `frames`/`sets`/`still`、能逐镜看和改、能接着拍。
- 9/26 起每个 agent 有笔记本(`studio_note`),记经验、偏好和工具问题。

### 一部片的时间花在哪

以 CHANGELOG 里实测的数字,一部 4 镜、20 秒、竖屏的 H3 片:

| 步骤 | 单次 | 一部片 | 来源 |
|---|---|---|---|
| 场景图 / 首帧(快速出图) | ~40 s | ~3–5 min | 552f4ca |
| H3 拍一个镜头 | ~712 s | **~47 min** | Montage 一节(五饼二鱼) |
| MiniMax Music 3 | ~67 s / 每秒音乐 | **~20–25 min** | 678dcc7 |
| 母带 + 片名 + 调色 + 放大 | ~3 s | ~3 s | cfa9e6e |

出图提速之后,**视频和配乐占了九成以上**。而且配乐现在是所有镜头拍完**之后**才开始做(`FilmStudio.swift` 里 `makeMusic` 在 `film.state = .cutting` 之后调用),两段时间是串起来的。

## 差什么,按先后

### 1. 先看预览,再正式拍 — 一天能出几部片

**问题**: H3 一个镜头 10 分钟以上,拍完才知道镜头不对,重拍又是 10 分钟。
**做法**:
- 新增 `stop_after: "preview"`:首帧确定后,每镜先用 LTX 出一个低分辨率预览(CHANGELOG 实测 LTX-2.3 int4 4 s 704×448 约 83 s),交给 agent 和人看。
- 预览过了再 `film_continue` 走 H3 正式拍;不过的镜头 `film_edit` 改了再预览,不碰 H3。
- 配乐不等镜头:片长在分镜后就知道(镜数 × 每镜秒数),分镜一定就开始作曲。**先确认盒子能否同时跑 H3 和 Music 3**;不能的话,至少排在预览阶段、H3 之前。

**验收**: 同一个题材,一次过的片子总时长不变或更短;有一镜要重拍的片子,节省 ≥ 一个 H3 镜头的时间。

### 2. 回归题材集 — 修好一部不弄坏另一部

**问题**: 最近的修复几乎都来自"海边漫步者"一部片。修的是真问题,但没有东西保证别的题材没被弄坏。
**做法**:
- `docs/studio-briefs/`(或 `scripts/studio-eval/`)放 6–10 个固定题材,覆盖:单人走动、双人对话、无人风景、动物、快动作、夜景、多场景。
- 每个题材跑到 `stop_after: "frames"`(便宜)即可做大部分检查;每周或大改之后跑一次全片。
- 自动打分,尽量复用已有的:
  - 空镜 / 没选角 —— Film 现在已经会报错
  - 首帧与演员一致 —— 已有的 vision 模型描述 + Jev/Laya 的"是否符合计划"
  - 片长、响度(−16 LUFS 附近)、结尾是否黑场 —— ffmpeg 可测
- 结果写成一张表(题材 × 指标 × 提交),存进仓库。

**验收**: 每个影响 Film 的提交,都能说出"回归集 N 个题材,哪些变好、哪些变差"。

### 3. 工作台之间的交接 — 不合并,只传递

**问题**: 四个 agent 分开是对的,但一部完整的片要用到几个台子的产出:Motion 做的动作给 Film 用,Comfy 出的图当首帧,Film 的镜头进 Montage 剪。现在只能人来搬。
**做法**:
- 一个 `studio_handoff(to, what, files, note)` 工具:把产出和一句说明交给另一个台子。对方 agent 在它自己的对话里收到一条消息,决定接不接。
- 产出放在共享的 `Studio/Shared/<handoff-id>/`,各台子只读。
- 不做"总 agent"。如果以后需要"制片人",它也只是第五个台子,用 handoff 发活,不直接调别人的工具。

**验收**: "Motion 做个转身 → 交给 Film 当第三镜"能由两个 agent 完成,人只说一句话。

### 4. 笔记本闭环 — agent 报的问题有人收

**问题**: `studio_note` 记下了工具问题,但要开发者自己去翻四个文件夹。
**做法**:
- 每天一次把四本笔记里**新增的**"工具问题"条目汇总成一份清单(或 GitHub issue,带来源台子和日期)。
- 修了之后在笔记里标"已修 @ 提交号",agent 下次启动能读到,不再绕着走。

**验收**: 每条工具问题都有状态:未处理 / 已修 / 不修(附原因)。

### 5. 更长的片、会说话的人

**问题**: 现在是一个场景、20 秒上下、只有旁白。
**做法**(在 1–3 稳了之后):
- 片子分"场 → 镜"两层,每场有自己的地点和演员,转场规则明确。
- 角色对白:按角色 TTS + 口型。Companion 模式已有视位轨道(`VisemeTrack.swift`),先评估能否用于拍出来的镜头。
- 目标:1–3 分钟、3–5 场、有对白的短片。

---

## 不做什么

- **不把四个 agent 合成一个**。9/25 试过又撤回("我后悔了……他们是独立分开的")。
- **不接按调用计费的云端生成 API** 作为默认路径。本地、盒子、订阅优先;云端最多作为明示的备选。
- **不为了快而降画质**,除非回归集证明看不出差别(快速出图就是这样验的)。

---

## 顺序

1 和 2 可以同时开始 —— 1 决定一天出几部片,2 决定加东西会不会退步。3 在 1 之后做(预览阶段的产出是最先需要交接的)。4 很小,随时可以插进来。5 等前面都稳了再做。
